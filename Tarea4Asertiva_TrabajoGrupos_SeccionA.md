## 1. Descripción de la Propuesta de Comunicación

Nuestra propuesta busca organizar la comunicación de un equipo de desarrollo de software 100% virtual, resolviendo problemas comunes como mensajes perdidos y reuniones improductivas mediante los siguientes pilares:

- **Reglas de Netiqueta:** Exigimos contexto en cada mensaje, respetamos los horarios de trabajo (evitando urgencias fuera de horario) y mantenemos un tono respetuoso que separa la crítica al código de la persona.
- **Uso de Hilos y Prioridades:** Utilizamos hilos por tema (bug, feature, decisión de diseño) para no saturar los canales generales. Clasificamos la urgencia en: **bloqueante**, **importante** y **puede esperar**.
- **Herramientas Colaborativas:** Implementamos GitHub Issues para tareas (con etiquetas y checklists) y Pull Requests para centralizar las discusiones técnicas sobre los cambios en el código.
- **Ownership de Documentos:** Cada archivo clave (README, wiki técnica, backlog) tiene un dueño rotativo por sprint, encargado de mantenerlo actualizado y resolver dudas.
- **Roles para Reuniones Remotas:** Rotamos dos roles para garantizar la eficiencia:
  - **Moderador:** Prepara la agenda y guía la conversación.
  - **Timekeeper:** Controla el tiempo de cada punto a tratar.
- **Plan de Fallback:** Si la videollamada falla, el equipo migra al chat de texto. Si alguien se desconecta, el moderador envía un resumen escrito; si la reunión se cancela por completo, se pasa a un modelo de aportes asincrónicos.
